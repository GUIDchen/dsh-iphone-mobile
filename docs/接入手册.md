# 接入手册

示例中的域名、节点名一律是占位符，请替换为自己的值。

## 零、先起网关（两种通道都需要）

~~~bash
dsh web                 # 终端 A：保持默认 loopback 监听
npm start               # 终端 B：网关监听 127.0.0.1:3081
cat ~/.dsh-mobile/token # 取得访问令牌
~~~

手机首次访问需带令牌换 Cookie：https://入口地址/login?token=<令牌>

注意：不要用 dsh web --host 0.0.0.0 直接暴露。围栏要求 Host 是 loopback 或 --trusted-host；
如果坚持不经网关直连，必须给 dsh web 加 --trusted-host 你的域名，且此时既没有认证层也没有移动端 PWA 层。
两条隧道脚本默认都指向网关（3081），这是有意为之。

## 一、Tailscale 私有通道

~~~bash
chmod +x scripts/setup-tailscale.sh
./scripts/setup-tailscale.sh
~~~

脚本反代的是网关 127.0.0.1:3081（可用 GATEWAY_PORT 覆盖）。**不要指向 dsh web 的 3080**：
tailscale serve 会带上 ts.net 主机名，直连 3080 会被 /api 信任围栏 403。

验证：手机关闭 Wi-Fi 只用蜂窝网络，打开脚本输出的 https 地址，完成令牌登录后进入界面。

## 二、Cloudflare Tunnel 公网通道（需要域名）

~~~bash
DOMAIN=dsh.example.com ./scripts/setup-cloudflare-tunnel.sh
~~~

脚本写入 ingress 指向网关 127.0.0.1:3081（可用 GATEWAY_PORT 覆盖）。cloudflared 默认保留原始 Host，
公网域名直连 dsh web 同样会被围栏 403，所以这里必须走网关。
随后在 Zero Trust 控制台为该域名建 Access 应用并添加邮箱一次性验证码策略。

换源后必做：重新「添加到主屏幕」，并重新订阅推送一次。

## 三、Capacitor 壳与 APNs（需要付费开发者账号）

免费 Apple 账号无法创建带推送权限的 App ID。

~~~bash
pnpm add @capacitor/core @capacitor/cli @capacitor/ios @capacitor/push-notifications @capacitor/app
npx cap init "DSH Mobile" com.example.dshmobile --web-dir=dist
npx cap add ios
npx cap sync ios
npx cap open ios
~~~

Xcode 内选择 Team，开启 Push Notifications 能力，Background Modes 勾选 Remote notifications。
Apple Developer → Keys 创建 APNs 密钥并下载 .p8（仅一次），记下 Key ID 与 Team ID 写入 .env。
