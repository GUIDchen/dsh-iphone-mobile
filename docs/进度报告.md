## 已修复缺陷与已纠正的设计错误

1. 代理改写 HTML 后仍保留上游 Transfer-Encoding: chunked 并设置 Content-Length，浏览器解析失败。
   已改为写入定长并删除 chunked 头；由自测脚本首次运行时捕获。
2. 早期文档按「SSE + since 游标回放」设计续传，与真实契约不符。契约明确：mux 的 since 在 v1 未实现，
   重连 = 重开流 + 重拉历史；宿主会自动重放未处理的审批帧。docs/架构与协议.md 已更正。
3. 隧道脚本原先默认反代 dsh web 的 3080。但 tailscale serve 与 cloudflared 都会带上外部主机名，
   直连 3080 会被 /api 信任围栏 403 —— 照着脚本做会得到一套「打不开」的接入流程。
   已改为默认指向网关 3081，并在接入手册里写明原因。
4. Service Worker 注册在 /m/ 作用域，无法控制根路径页面，导致 navigator.serviceWorker.ready 永不 resolve，
   推送入口按钮因此永远不出现。curl 抓不到这个问题，是真实浏览器验证暴露的。
   已改为：响应头 service-worker-allowed: / + 以 scope 注册根路径，并加了一条回归断言。

## 压测方法与判定（脚本就绪，结果待执行）

| 场景 | 注入方式 | 判定 |
| --- | --- | --- |
| 锁屏挂起 | 流式输出中锁屏 60 秒 | 重开流后按 seq 去重，消息不缺失不错序 |
| 弱网丢包 | LOSS=3 DELAY=200 ./scripts/stress-test.sh | 重连次数有界，退避间隔递增 |
| 飞行模式 | 30 秒后恢复 | 数秒内自动重连 |

判定工具：node scripts/check-stream.mjs < logs/events.jsonl。

## 遗留风险

1. 网关令牌是单因子；公网入口必须叠加 Access 或等效身份层。
2. 关闭隧道时既连不上页面也收不到推送；需壳 + APNs 补齐。
3. Service Worker 暂不缓存页面，离线时只有一个空壳。
4. 通知点击目前跳首页，未定位到具体会话（GUI 路由格式未核实）。
